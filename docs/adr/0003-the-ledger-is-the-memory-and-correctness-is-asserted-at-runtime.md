# The Experiment Ledger is the cycle's memory, and correctness is asserted at runtime

A CRISP-DS turn is only worth running if the next turn can read what this one measured, and the failure mode of every measurement here is silent — a number that comes out plausible and biased. So the project keeps an append-only **Experiment Ledger** written by exactly one code path, promotes an **Incumbent** only by explicit human command, and verifies its own correctness with asserts that run on every execution instead of with a unit-test suite. Two of these look like omissions from the outside — there is no test directory worth the name, and nothing automatically records "the best model" — so they are recorded here to stop them being "fixed".

## Considered options

**Where the memory of a turn lives.** A hand-maintained Markdown table, a CSV, a hosted tracker (MLflow / W&B), or an append-only JSONL committed with the repo. JSONL wins on three properties this project actually needs: two runs appending never conflict in git, the record is grepable from the same terminal the runs happen in, and it is versioned alongside the code that produced it — a **Run Record** and the `src/` it ran is one commit. A hosted tracker adds an account, a service and a second source of truth for a repo whose whole lifespan is eight days. `ledger/runs.jsonl` holds the Comparison Runs; `ledger/submissions.jsonl` holds the submissions, separately, because a submission has a `public_score` and no **Paired Delta** and merging the two schemas into one file destroys the grep.

**Who promotes the Incumbent.** The `runner` could evaluate the promotion rule from issue #6 and flip the flag itself. It does not: it prints the verdict — passes, fails, or needs a **Confirmation Run** — and stops. Promotion is the only write to the ledger that is a judgement rather than an observed fact, and it is made under deadline pressure, which is the exact condition under which an automatic rule turns a noise-sized delta into the reference that every later measurement is taken against. `uv run promote <run_id>` writes the judgement, the delta, and which of the three rules authorised it.

**How correctness is checked.** A unit-test suite, or asserts inside the pipeline. The three things ADR-0001 says fail silently — a transform fitted outside the training fold, digit decomposition computed after scaling, `Age` losing its individual values — cannot be caught by a test that nobody runs at 2am on day seven. They are caught by asserts that cannot be skipped because they are on the path: the sha256 of the fold-id vector, 45 distinct addressable `Age` values, zero `NaN` in the **Baseline Frame**, and the **Model Adapter** refusing a `fit` that receives validation rows. One real test survives in `tests/`, because it cannot be expressed as a runtime assert: the Adapter on a tiny synthetic frame, proving a target encoding never sees its own row.

## Consequences

- **`src/runner.py` is the only writer of `ledger/runs.jsonl`**, and experiments are therefore *declarations*, not scripts: each file in `src/experiments/` is a named `ExperimentConfig` with a docstring naming the hypothesis it tests, launched through one entry point. An experiment that could run itself is an experiment that can forget to record itself, and an unrecorded run is a run that did not happen.
- **A `run_id` is `<timestamp>-<experiment name>`, not a hash of the config.** The **Confirmation Run** protocol deliberately executes one config three times; hashing the config as identity would collide exactly on the repetitions the protocol depends on. The config hash is still written, as a `config_sha` field, so "have I already tried this?" stays one grep away.
- **The OOF prediction vector of every run is kept** in `runs/<run_id>/oof.npy`, outside git. It is what makes a **Paired Delta** computable between two configurations that were never compared when they ran — the ledger records the numbers, the vectors let new questions be asked of old runs without retraining. `runs/` is gitignored for the same reason `data/` is.
- **The Baseline Frame is never cached.** It is rebuilt from `read_csv` in file order on every run, because issue #6 ties reproducibility to that row order and because the most common change in turn 1 *is* a change to the Frame — a parquet cache would go stale precisely when it matters most. If rebuild time is ever measured as a bottleneck, that is a ticket, not a premature optimisation.
- **Nothing produced in a notebook may enter the ledger.** Notebooks read data and call into `src/`; they never redefine a transform. That rule is what makes it safe to commit EDA notebooks *with* their outputs — a stale output documents what was seen on a given day and can never contaminate a measurement.

Terms in capitals are defined in `CONTEXT.md`. The promotion rule comes from issue #6, the silent failure modes from ADR-0001 and issue #4.
